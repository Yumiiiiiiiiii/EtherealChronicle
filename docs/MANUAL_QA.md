# MANUAL_QA — 実クライアント検証チェックリスト（10〜15分）

対象: EtherealChronicle（master 78436ea 以降）/ Paper 26.3-257 / Minecraft Java 26.3。
自動化できなかった項目（HUD・視線判定・死亡ドロップ・bound保護の一部・テレグラフ・ダンジョン移動）だけを人が確認します。
結果欄に ✅/❌ とメモを記入し、末尾の「報告」をまとめてリードへ返してください。

## 0. 自動化の調査結果（なぜ手動か）
- bot: mineflayer 4.39 / minecraft-protocol 1.68 は最大 26.1 まで。26.3 のハンドシェイク/パケット定義が無く接続できない（`scripts/bot` で実測済み）。
- クライアント: `%APPDATA%\.minecraft\versions\26.3` には `26.3.json` しか無く、クライアント jar・assets・同梱 JRE は未ダウンロード（ランチャーが初回起動時に取得）。ランチャーはユーザーのMicrosoftアカウント前提のため自動起動はしない。
- 画面操作: QAエージェントにはデスクトップ操作/画面キャプチャ権限が無い（ブラウザ操作のみ）。PowerShell の SendInput で他アプリを操作する案は、ユーザーのデスクトップを勝手に操作することになるため採用しない。
- 結論: 実クライアント検証は人手。サーバー側ロジックは MockBukkit / コンソールsim（`docs/TESTING.md`）で検証済み。

## 1. 準備（約3分）
1. サーバー起動: リポジトリ直下で `./scripts/dev-server.ps1`（EULA は承諾済み。ビルド＋起動。コンソールにコマンド入力可）。`Done` が出て `冒険システムの準備が完了しました。` が出るまで待つ。
2. 起動構成 26.3 のクライアントで マルチプレイ → ダイレクト接続 `127.0.0.1:25565`（オフラインモード）。
3. サーバーコンソールで自分をOPに: `op <あなたのID>`。
4. 初期化したい場合: サーバー停止 → `plugins/EtherealChronicle/playerdata/<uuid>.yml*` を削除 → 再起動。
5. 以降 `<me>` は自分のプレイヤー名。チャットコマンドは OP で実行。
6. 負荷確認用: `/spark healthreport`（spark 導入済み）。

## 5. リソースパックとGUIテーマの確認

1. `config.yml` の `resource_pack.required: true` と有効な配信方法を設定し、新規 UUID のプレイヤーで初回ログインします。プロフィール読み込み中に職業選択GUIより先に必須プロンプトが表示されることを確認します。再接続でも要求が出ること、拒否すると接続が切れることを確認します。
2. `ui.theme.mode` を `icons_only`、`full`、`off` に変更してサーバーを起動し直すか、管理者の `/ec reload` で設定を読み直します。開いているGUIを閉じ、職業選択・ショップ・図鑑を開き直して比較します。表示中の画面は自動再描画されません。
3. 必須パックの拒否時、クライアントによっては切断画面にサーバー側の日本語理由が表示されず、Minecraft標準の「サーバーにはリソースパックが必要です」だけが出る場合があります。サーバーリストのMOTDにも「サーバーリソースパックを有効にして再接続してください」と案内してください。
